## 三、合成数据纪律

### 3.1 总则

- **演示与基准数据一律合成**，禁止使用真实交割单、真实姓名、真实股东账号、真实资金账号、真实证券代码对应的真实持仓。
- 合成交割单由生成器程序化产出，**固定 seed、不读时钟、不读 stdlib random**；`--check` 与重生成结果逐字节比对（禁手改）。
- 合成数据必须**刻意注入每一类情形**（见 §3.4 覆盖度），否则真值矩阵在样例上不可见。

### 3.2 假证券代码白名单

- **代码块**：`699000`–`699099`（6 位、形态合法、便于解析器原样处理），**声明为虚构代码**，不对应任何真实上市公司；
- **名称前缀**：所有合成证券名称必须以 `示例` 开头（`示例科技甲`、`示例银行乙`、`示例基金丙`、`示例转债丁` 等），使"撞上真实代码"在肉眼与脚本两层都可见；
- **生成器硬约束**：只允许白名单内的代码与名称前缀组合，白名单外新增须先在本节登记；
- **诚实条款**：若未来 `699xxx` 段被真实启用，**以"示例"名称前缀与本白名单为准**；检查脚本对样例中断言"代码 ∈ 白名单 且 名称以 `示例` 开头"。

### 3.3 假账号白名单

- **资金账号**：`Y0000001`–`Y0000009`（`Y` 前缀 + 7 位数字）；
- **股东账号**：`A000000001`–`A000000009`（`A` 前缀 + 9 位数字）；
- **账户别名**：`示例账户一`–`示例账户九`；
- **禁止**：任何 8 位以上纯数字账号串、任何真实券商账号形态、任何身份证号形态；检查脚本对样例与真值台账做正则扫描（纯数字长串即 FAIL）。
- **打码口径**：报告中对上述账号也按"首尾片段"规则打码（与真实账号同一策略，避免"样例看起来是明文、真实数据才打码"的双口径）。

### 3.4 真值台账纪律（M1 核心）

- 真值台账 = **程序化生成的期望标注**，与合成交割单**同源生成**（同一 seed / 同一生成逻辑），故标注与数据必然一致。
- 真值台账逐条登记：
  - **已知成本**：每笔成交在 **FIFO 与移动加权两种口径**下的持仓成本与已实现收益；
  - **已知公司行为**：分红 / 送转 / 配股 / 拆分 / 分红再投事件的份额与成本调整前后值；
  - **已知 XIRR**：每个账户与合并视图在各估值日的 XIRR 期望值（由生成器用同一算法定义算出的**参考值**，并另附一份**独立手工算例**作为第二判据）；
  - **已知划转**：账户间资金划转清单（合并视图必须抵消）。
- **真值库只存"输入 + 期望"，观测由基准运行时实算**——把观测也冻进真值库，评测会退化成"比对两个冻结字典"，引擎坏掉也全绿。
- **分文件登记**：导入层在 `data/truth/import_truth.json`；成本层在 `data/truth/cost_truth.json`（M2 追加）。两份都由生成器产出，**生成器不 import 引擎**——成本真值用 `Fraction` 精确数量 + 整数分独立复算，与引擎是两套实现。
- **成本真值的场景范围**：`cost_truth.scenario.files` 显式列出参与成本场景的 4 份样例。其余样例是这些账户的子集 / 副本，**全部一起导入会重复计数**，所以真值把范围写死，而不是"把所有样例都算进去"。
- **覆盖度双登记**：真值台账的 `coverage` 段逐形态登记 `total / sampled`，分子必须等于分母（测试锁定）；形态至少覆盖——
  - 导入：两类真实格式（海通 xlsx / 华西 tab+GB18030）各至少 1 份、UTF-8 CSV、GB18030 CSV、`="..."` 单元格、缺列、错位列、空文件、仅表头、超长备注、千分位金额；
  - 成本：同日多笔、部分卖出、清仓后再买入、送转后卖出、双口径产生差异的构造用例；
  - 公司行为：分红、送转、配股、拆分、分红再投、**无法识别（必须进待确认）**；
  - 归因：单笔一次性投入、多笔定投、中途大额赎回、负收益、零收益、期末市值为 0；
  - 合并：两账户、三账户、账户间划转、同名标的重叠持仓。
- **"无法识别"必须被注入**：样例必须包含刻意构造的未知业务名称行，否则"未识别行进待确认队列"这条纪律在基准上不可见。

### 3.5 样例文件命名与豁免

- 命名：`htsec-demo-*.xlsx`、`huaxi-demo-*.xls`、`generic-demo-*.csv`、`generic-demo-*.tsv`；
- 这些样例**要入仓**（见 `.gitignore` 末尾的豁免说明），由生成器产出并配 `--check` 位级守门；
- **用户真实交割单永不入仓**：本机私有文件放 `_private/` 或 `data/**/_private/`（已在 `.gitignore` 忽略）。

## 四、数值口径纪律（**唯一定义处**）

> 引擎、报告、基准、文档注记全部引用本节。**任何其他文件不得再写一份口径表述。**

### 4.1 成本口径

| 项 | 定义 |
|---|---|
| FIFO | 卖出时按**买入时间升序**消耗持仓批次；同一时点存在多批时按 `成交日期 + 成交时间 + 原始行号` 升序；每批成本含该批买入费用 |
| 移动加权平均 | 每次买入后重算：`新单位成本 = (原持仓总成本 + 本次买入金额 + 本次买入费用) / (原持仓数量 + 本次买入数量)`；卖出不改变单位成本，仅按单位成本结转已实现收益 |
| 口径选择 | 显式参数 `--cost-method fifo|wavg`，**无默认值**（必须指定，避免"用了哪个口径说不清"）；报告页眉强制标注 |
| 费用归属 | 佣金 / 印花税 / 过户费 / 其他费按交割单**实际列值**入账；买入费用计入成本，卖出费用冲减已实现收益；交割单未分列时按参数包中**显式分摊规则**处理并在报告标注"分摊口径" |
| 数量单位 | 股（整数）；基金份额保留 4 位小数（若扩展基金通道） |

#### 4.1.1 M2 落地的细则（引擎行为的唯一定义处）

| 项 | 定义 | 实现位置 |
|---|---|---|
| 成本载体 | **成本 = 整数分**；单位成本是展示值（6 位小数，四舍五入），权威值永远是整数分 | `ledger/positions.py` |
| 部分卖出拆分 | 按 `成本 × 卖出数量 / 持仓数量` 四舍五入到分；**整批取尽时不除法**，直接取该批全额，保证"各批之和 = 总成本"守恒 | `ledger/positions.py:allocate_cost` |
| 零成本份额（送股 / 拆分） | 份额按比例放大各批数量、**总成本不变**；FIFO 下批次数量放大按 4 位小数向下取整、余数归最后一批，保证数量之和精确 | `FifoBook.add_free` |
| 配股 / 红利再投 | 配股 = 有数量 + 有对价 + 现金流出 → 视同买入（对价 + 费用计入成本）；红利再投 = 有数量 + 有对价 + **无现金流出** → 按对价计入成本（视同投入） | `ledger/model.py` |
| 现金事件 | 方向 other、无数量、有现金变动（转入 / 转出 / 红利 / 其他）→ 只影响资金余额，**不建仓** | `ledger/model.py` |
| 费用未分列的判定 | 只有**四项费用列全为 `None`** 才算"未分列"；此时按 `发生金额` 反推：买入/配股 `费用 = -发生金额 - 成交金额`，卖出 `费用 = 成交金额 - 发生金额`；反推为负即落 `FEE_IMPLIED_NEGATIVE`，不静默截断 | `analyze_row` |
| 费用来源标注 | `as_reported`（全部列有值）/ `partially_reported`（部分列有值）/ `derived_from_settlement`（全部无值但有发生金额）/ `not_reported`（无值且无法反推，按 0 计） | 每笔事件 `fee_source` |
| T+1 资金勾稽 | 首条带 `extra.cash_balance` 的行确定期初资金，之后逐行比对 `期初 + 累计发生金额`；不平落 `CASH_BALANCE_MISMATCH`（带期望值 / 实际值 / 差额），**不中断整份账本** | `_reconcile` |
| 股份余额勾稽 | 逐行比对引擎持仓与 `extra.share_balance`，超出 `bench_thresholds.position_quantity_tolerance_shares`（1 股）落 `SHARE_BALANCE_MISMATCH` | `_reconcile` |
| 超卖 | 卖出数量超过持仓时，能匹配的先结转，未匹配部分落 `INSUFFICIENT_POSITION`，**不把持仓冲成负数** | `_apply_row` |
| 每日快照 | 按**有流水的交易日**生成（不补空自然日）；只记数量 > 0 的持仓；日期升序、账户与标的名升序 | `_snapshot` |
| 分账户 | 已登记账户按 `account_id` 分组；未登记账户按 `source_file + 股东账号` 单独成组，**不并入任何默认账户** | `model.account_key` |
| 退出码 | 0 = 无勾稽问题；1 = 有 `invalid` 或有未登记账户；2 = 缺口径 / 流水缺失 / 形态不符 | `pipeline/cost_cmd.py` |

### 4.2 XIRR 定义与算法

- **定义**：求 `r` 使 `Σ CF_i / (1 + r)^(d_i - d_0)/365 = 0`，其中 `d_i` 为现金流日期，`d_0` 为首笔现金流日期，`365` 为固定年基（**不用 360，不做闰年调整**）。
- **现金流符号约定**：买入/转入为负，卖出/分红/转出/期末市值为正；期末市值记在估值日。
- **求解**：Newton–Raphson，初值 `r0 = 0.1`，收敛判据 `|r_{n+1} - r_n| < 1e-12`，最多 `100` 次迭代；不收敛时退化为**二分法**，区间 `[-0.999999, 1e6]`，收敛判据 `|NPV| < 1e-6`（货币单位），最多 `200` 次迭代。
- **无解处理**：区间两端 NPV 同号 → 抛出 `XIRR_NO_SOLUTION` 并以退出码 1 结束，**不输出近似值、不打印 NaN**。
- **确定性**：同一输入重复运行结果**逐位一致**（不使用随机初值、不并发求和；浮点累加按固定顺序）。

### 4.3 TWR 定义

- **分段**：按**外部现金流发生日**切段；每段收益率 `r_t = (V_end - CF_t) / V_start - 1`（`CF_t` 为该时点净外部现金流）；
- **估值点**：`--twr-basis cashflow|daily`（默认 `cashflow`），`daily` 模式用**每日持仓快照 × 当日市值**；两种模式都**不插值**，缺市值日直接报 `VALUATION_MISSING`；
- **累计**：`TWR = Π(1 + r_t) - 1`，按日期升序连乘，顺序固定。

### 4.4 误差容忍度（唯一来源）

| 对象 | 容忍度 | 说明 |
|---|---|---|
| 持仓数量（对券商 App） | **≤ 1 股** | 用于吸收送转碎股/四舍五入差异；超出即视为引擎缺陷 |
| 金额（对券商 App） | **≤ 0.01 元** | 用于吸收显示精度差异 |
| XIRR（对 Excel `XIRR` 手工对照） | **相对误差 < 0.01%** | 即 `|r_ours - r_excel| / max(|r_excel|, 1e-9) < 1e-4` |
| 已实现 + 未实现 vs 总收益 | **≤ 0.01 元** | 拆分守恒断言 |
| 合并前后总收益（划转抵消） | **≤ 0.01 元** | 划转抵消正确性断言 |
| 报告字节一致性 | **完全一致** | 双跑 sha256 相同 |
| 基准覆盖率 | 分子 = 分母 | 逐形态登记，测试锁定 |

### 4.5 默认值与"经验默认"标注

- 所有可配置参数（日期区间、估值日、费用分摊规则、行业映射、TWR 估值点）**默认值均为经验示例值**，注明"非官方"；
- 阈值与默认值只写在参数包 `params` 中，其他位置引用不复制。

## 五、隐私红线

- 交割单是**极敏感数据**：含真实姓名、股东账号、资金账号、全部成交与余额、持仓规模。
- **纯本地零上传**：无网络调用、无账号、无遥测；所有中间件与报告落本机。
- **报告阶段打码**：账号在生成阶段打码，HTML / JSON 中不出现完整账号。
- **真实数据隔离**：真实交割单只在本机处理，永不入仓；样例一律合成（§三）。
- **不登录券商**：不接收、不存储、不传输任何券商账号或密码。
