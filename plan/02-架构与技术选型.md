# plan/02 — 架构与技术选型

> 本文件回答"用什么东西、怎么分层、为什么这样选"。数值口径一律引用
> `data/README.md §四`，本文件不复制第二份。

## 一、交付形态

| 项 | 决定 |
|---|---|
| 形态 | **纯本地 Python CLI + 单文件 HTML 报告**（唯一形态） |
| 运行方式 | `python -m investment_attribution <cmd>`；安装后 `investment-attribution <cmd>` |
| 服务端 | **无**。不起 HTTP 服务、不开端口、不监听 |
| 数据存储 | 用户本机文件系统（JSON / HTML 产物）；**不引入数据库** |
| 前端 | 单文件 HTML，CSS/JS **全部内联**，零 CDN、零外链 |
| Python | **3.8+**（本地与 CI 双通道：3.8 / 3.12） |
| 第三方依赖 | **核心零依赖**；测试期仅 `pytest` |

## 二、分层

```
CLI 层        cli.py / __main__.py
              ├─ 参数解析与语义校验（None 与 falsy 严格区分）
              ├─ 退出码转译（领域异常 → 契约退出码）
              └─ 不承载任何业务计算

编排层        pipeline/<command>.py（M1 起）
              ├─ import / cost / pnl / corporate-actions / attribution / merge / report / run
              ├─ 每个子命令 = 一个纯函数，输入输出皆可序列化
              └─ CLI 与"直调编排函数"行为等价（三方对账测试锁定）

引擎层        ingest/  ledger/  actions/  attribution/  report/
              ├─ ingest/       编码探测、单元格壳清洗、列名归一、行级台账
              ├─ ledger/       成本引擎（FIFO / 移动加权）、持仓快照、余额勾稽（M2 已落地）
              ├─ actions/      公司行为规则表 + 人工确认队列
              ├─ attribution/  XIRR / TWR / 收益分解
              └─ report/       单文件 HTML 渲染 + report_data.json

基础设施层    paths.py / serialize.py / manifest.py / errors.py / exit_codes.py / netguard.py
              ├─ 数据目录解析（显式 > 环境变量 > 源码树探测，不落 CWD）
              ├─ 确定性写盘（唯一 JSON 写盘入口）
              ├─ 契约清单加载与结构校验
              └─ 零上传静态门禁
```

**分层红线**：
1. 渲染层（`report/`）**零判定**——只消费引擎结论，不重算任何数字；用 AST 门禁锁死。
2. 引擎层**零网络**——静态 import 审计（M0 已落地）+ 运行期 socket 探针（M4 落地）。
3. 编排层**唯一业务入口**——CLI 只做参数与转译，禁止在 `cli.py` 里写业务规则。

## 三、关键选型理由

### 3.1 为什么零第三方依赖

- **可复现性**：结论可复跑、可审计，依赖面越小，跨机器复现的变量越少。
- **隐私面**：无网络库依赖，"零上传"从声明变成可静态核验的事实。
- **安装面**：`pip install -e .` 秒装，干净环境验证不受镜像/网络影响。
- **代价**：xlsx 读写要自己写最小 OOXML writer（`ZIP_STORED` + 固定
  `date_time` + `create_system=0`），CSV/TSV 用标准库；这项成本换来
  逐字节确定性，值得。

### 3.2 为什么不用 SQLite 作为主存储

交割单规模（数千到数万行）完全可控，JSON + 内存计算足够；引入持久层会
带来"唯一键含 NULL 绕过幂等""created_at 读时钟破坏双跑一致"等一整类坑。
**中间产物一律落盘为 JSON**，用户可单步复查（`--out-dir`）。

### 3.3 为什么报告是单文件 HTML

`report_data.json` 与 HTML 同源、同一次渲染产生；HTML 内联全部样式与脚本，
**断网可开、可直接归档、可发给别人**。用 AST 断言"渲染层不 import 引擎"，
用出口常驻断言"零外部资源"，用双跑 sha256 锁字节一致性。

### 3.4 为什么成本口径无默认值

`--cost-method fifo|wavg` **必须显式指定**。券商默认口径各不相同，给默认值
等于让用户在不知情的情况下拿到另一个口径的数字——这正是本题要解决的问题。
报告页眉强制标注本次口径。

## 四、模块接口（骨架已定，M1–M5 填充实现）

| 模块 | 入口 | 输入 | 输出 |
|---|---|---|---|
| ingest | `ingest.load(files, account_map)` | 交割单文件路径列表 | 统一流水 + 行级错误台账 + 文件指纹台账 |
| ledger | `ledger.build_holdings(ledger_path, method, data_dir)` | 统一流水 + 口径 | 持仓台账 + 每日快照 + 已实现/未实现 |
| actions | `actions.apply(holdings, rows, rules)` | 台账 + 公司行为行 + 规则表 | 事件台账 + 待确认队列 + 调整后台账 |
| attribution | `attribution.compute(...)` | 台账 + 期末市值 + 可选基准 | XIRR / TWR / 分解表 / 费用拖累 |
| merge | `merge.accounts(...)` | 分账户结果 + 账户登记 + 划转 | 合并视图 + 划转抵消台账 |
| report | `report.render(...)` | 全部派生结果 | 单文件 HTML + `report_data.json` |

**中间表示（统一流水一行）**：

```
source_file, source_sha256, source_line_no, account_id, symbol, name,
business, trade_date, trade_time, quantity, price, amount, settlement_amount,
commission, stamp_tax, transfer_fee, other_fee, direction, contract_no, trade_no
```

## 五、确定性设计

| 关注点 | 做法 |
|---|---|
| 排序 | 全链路排序键 = `(trade_date, trade_time, source_line_no)`；`source_line_no` 是源文件行号，不是数组下标 |
| 时钟 | 引擎与渲染层**不读系统时钟**；报告不含生成时间戳 |
| 随机 | 禁用 `random`；生成器用自研确定性 RNG（splitmix64 类） |
| 浮点 | 金额一律用 `Decimal` 或"整数分"累计，固定运算顺序，禁止并发求和 |
| 写盘 | 唯一入口 `serialize.write_json_atomic`：`sort_keys` + LF + 结尾换行 + 原子 rename |
| 字节 | 同输入双跑 sha256 相同，测试锁定；zip 型产物钉死 `create_system` 与 `date_time` |

## 六、失败与降级语义

| 情形 | 语义 |
|---|---|
| 文件缺失 / 编码探测全失败 / 缺必填列 / 空文件 | **exit 2**（形态失败，整份文件不可用） |
| 文件可用但部分行不合格 | **exit 1**（行级失败，逐条进异常台账并真打印） |
| 模块未落地 | **exit 3**（阶段未就绪，不产出伪造结果） |
| 规则无法识别的公司行为 | 进**待确认队列**，`exit 1`，不静默丢弃 |
| 无基准 CSV | 正常出结果，只是不显示超额列，**exit 0** |
| XIRR 无解 | `XIRR_NO_SOLUTION`，`exit 1`，**不输出近似值、不打印 NaN** |

## 七、风险与缓解

| 风险 | 缓解 |
|---|---|
| 券商格式漂移（列名改版） | 列名别名表为冻结产物 + 未登记列记 `unknown`，行仍可用；不对齐的行不入库 |
| 公司行为自动识别出错 | 规则表只认能确定的，其余进待确认队列；调整前后两组数可逆可追溯 |
| 浮点误差累积 | 整数分 / Decimal + 固定顺序 + 守恒断言（拆分之和 = 总收益） |
| 报告泄露敏感账号 | 生成阶段打码 + 静态扫描无完整账号形态 |
| 无人维护的"支持全部券商"承诺 | 明确只承诺两类实测格式 + 通用映射；其余落 `unknown` 并列清单 |
