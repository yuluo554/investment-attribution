### M5 已知偏差（写清以免被当成 bug）

1. **`run` 在随包样例上返回 1，不是 0**。样例刻意注入了一条规则表认不出的
   现金行（`其他业务甲`），`corporate-actions` 按契约返回 1（有待确认行），
   `run` 取各步最大值故为 1。这是**数据结论**；把它改成 0 才是隐瞒问题。
   要验"exit 0"，用 `merge` / `report` 两条命令：它们在样例上均为 0。
2. **B1 不比 `raw_line` 与 `fingerprint.encoding/delimiter`**。真值的
   `raw_line` 存的是**源文件原文**，导入台账存的是**解码后逐格重新拼接**
   （含引号的单元格不会重新加引号）；真值的 `encoding/delimiter` 是**声明形态**
   （`binary-xlsx` / `utf-8` / 制表符），指纹里是**探测结果**（`xlsx` /
   `utf-8-sig` / `tab`）。两侧都正确，只是词汇不同；字节一致性由
   `fingerprint.sha256` 保证，行级错误由 `(source_line_no, reason_code)` 保证。
   已记入 `plan/HANDOFF-M6.md`。
3. **报告的输入路径按调用方传入原样记录**。`run` 用 `Path` 规范化拼接中间
   产物路径，因此做逐字节比对时 `--ledger` 要传与 `run` 相同形态的路径
   （`test_run_matches_per_command_byte_for_byte` 即按此断言）。
4. **报告退出码跟随上游**：`merged.json` 有 `invalid` 时报告仍生成，但退出码
   为 1——“渲染成功”不等于“账本没问题”，两者都必须让脚本调用方看得见。
