## 一、项目介绍

**痛点**：一个 A 股投资者的真实持仓分散在 2—4 家券商：主账户打新、副账户做可转债、老账户还留着几年前的成本、家里老人的账户由本人代管。券商客户端只告诉你"这个账户现在有多少股、成本价多少"，**没有任何一家客户端告诉你跨账户合计的真实收益率**——因为它既不知道你在别的券商的钱，也不会替你算清分红送转后的成本、更不会把佣金印花税过户费拆出来告诉你费用吃掉了多少收益。更麻烦的是：**成本口径本身有分歧**（先进先出 vs 移动加权），券商各自默认一种，迁移账户时口径一变，历史收益就对不上。

**需求证据（商业产品已验证付费意愿）**：同花顺投资账本 App Store 中国区 **36,274 个评分 / 4.84 分**，2016 年上线、**2026-10-13 仍在更新**，产品描述明确写"集中管理分散在不同账户、不同平台的股票和基金"——**"多账户集中管理"是被商业产品验证过的真实需求，且用户愿意为此持续使用一个专门的 App**（✅ 直连可取，见 §五；评分为页面快照，随页面变动）。

**用户规模（⬜ 二手口径，待核）**：中国结算口径 2025-06 末 A 股投资者总数**突破 2.4 亿**。⬜ **二手口径待核**：中国结算官网（chinaclear.cn）月报为动态页面，出题阶段未取到可直连的官方月报直链，故本数字**只作规模感辅助论据，不作硬锚点**，入库时须补官方直链核对。

**多账户合并的真实摩擦（✅ 二手实证）**：
- CSDN《通达信多账户管理》（2025-05-14）https://blog.csdn.net/wencaitouzi/article/details/147982719 —— 用户自发研究如何把多个账户放进同一视图；

**生态参照（必须区分，否则会误判竞品）**：

- `beancount`（**6090★**）：复式记账**引擎**，用 DSL 描述账目，需要会计素养才能写对分录——**不是"导入即出结果"的工具**；
- `deb-sig/double-entry-generator`（**729★**）：23 个 provider 把交割单转成 beancount 条目，**中国大陆券商仅海通/华西两家**，且只做"转条目"，不做成本引擎与归因；
- `ghostfolio`（**9494★**）：Web 端组合跟踪，**要部署服务、要联网行情、要账号**；
- `portfolio-performance`（**4109★**）：桌面组合工具，**146 个 PDF 导入器里无一中国大陆券商**；
- `TurtleTrace`（**51★**）：本地多账户，但**只支持 JSON 导入**，不给券商格式。

**组合空白结论**：**本地优先 + 零上传 + 不登录券商 + 中文券商交割单适配 + 公司行为还原 + 多账户 XIRR/TWR 归因 + 本地 HTML 报告** = 当前无人占位的组合。"能导入"的（double-entry-generator）不做归因；"能归因"的（ghostfolio / portfolio-performance）要联网、要部署、无中文券商格式。**本题占的是两者的交集。**

**格式实测（✅ 已核对样例列结构）**：

- **海通证券**样例 `.xlsx` 列齐全：`证券代码 / 证券名称 / 成交日期 / 成交时间 / 成交数量 / 成交价格 / 成交金额 / 发生金额 / 操作 / 合同号 / 成交号 / 手续费 / 印花税 / 过户费 / 其他费 / 资金本次余额 / 股份本次余额 / 股东账号 / 资金账号`；导出路径：e海通财 PC 客户端 → 查询 → 交割单 → 导出 Excel（格式文档：`deb-sig/double-entry-generator` 的 `docs/docs/providers/securities/htsec.md`）。
- **华西证券**样例 `.xls` **实为 Tab 分隔文本**，单元格带 `="..."` 前缀，列名如 `买卖日期 / 成交时间 / 业务名称 / 证券代码 / ...`，编码 **GB18030**——**这是典型的"格式动物园"**：扩展名骗人、编码非 UTF-8、单元格有公式壳。
- **不需行情也能算**：XIRR/TWR 只需要**交割单现金流 + 期末市值**（手工录入或本地 CSV），实时行情是**可选项**而非前置条件。这一点决定了本题可以做到"断网全流程可用"。

**为什么是工具而不是让 AI 聊天算（独特性拷问）**：交割单是**持久状态**——一次导入的几千行成交要跨会话留存，成本口径要跨年度一致，除权调整要能被后来的人工确认覆盖且可回溯；LLM 聊天既没有可审计的持久台账，也无法保证同一份输入两次跑出同一个数字。归因结论必须**可下钻到原始行**、**可复跑比对**，这是工具交付物才具备的性质。

## 二、任务要求

> **首期范围限定为五个模块**（M1–M5），基金 CSV / 手工模板、PDF 交割单、更多券商适配列扩展项（见本节末）。每模块写清**输入 / 输出 / 确定性纪律 / 验收**。
>
> **数值口径一律以 `data/README.md §四` 为唯一来源**（成本口径、XIRR 算法与收敛条件、误差容忍度），本文出现的阈值均为引用，不得手写第二份口径。

### 模块① 多券商导入适配层

- **输入**：用户在券商客户端自行导出的交割单文件，首期覆盖 **`.xls` / `.xlsx` / `.csv` / `.tsv`** 四种扩展名；已实测的两类真实格式为**海通（xlsx）**与**华西（.xls 实为 Tab 分隔文本、GB18030 编码、`="..."` 单元格前缀）**。
- **输出**：统一成交流水中间表示（每行：来源文件 / 文件 SHA-256 / 原始行号 / 账户标识 / 证券代码 / 证券名称 / 业务名称 / 成交日期 / 成交时间 / 数量 / 价格 / 金额 / 发生金额 / 各项费用 / 买卖方向 / 合同号 / 成交号）+ **行级错误台账** + **文件指纹台账** + **账户—股东账号映射**。
- **确定性纪律**：
  - **编码探测白名单**：按 `UTF-8(BOM) → UTF-8 → GB18030` 的**显式顺序**尝试，全部失败即报错并列出文件，**不猜测、不静默替换字符**；
  - **`="..."` 前缀清洗**：仅剥离形如 `="内容"` 的整个单元格包裹，剥离后仍非法的值落 `invalid`，**不做宽松修补**；
  - **列名归一化**：冻结的**别名表**（列名白名单 + 同义词映射），未登记列名记 `unknown`（行仍可用），**列对齐不可信的行不入库**（宁可少一行，不可把错位的值当对的）；
  - **逐行错误台账**：每条异常行**保留原始行文本、行号、失败原因**，可原样回放；禁止只留一句"解析失败"；
  - **文件 SHA-256 去重**：同内容文件（改名/改扩展名）识别为同一件，重复导入**不产生任何重复流水**，并在报告中列出被跳过的文件与已导入时间的对应关系；
  - **账户/股东账号映射不自动猜测**：多账户由用户显式登记，未登记的账号落"待确认"，不并入默认账户。
- **验收**：同一文件重复导入 **0 重复流水**；海通 / 华西两类真实样例（脱敏/合成替代版）**100% 入库**，逐行列值与原文件一致可回放。

### 模块② 交易账本与成本引擎

- **输入**：模块①的统一流水。
- **输出**：逐笔持仓成本台账、每日持仓快照、已实现/未实现收益、费用明细（佣金 / 印花税 / 过户费三件套分摊到笔）。
- **确定性纪律**：
  - **两种成本口径可选**：**FIFO（先进先出）** 与 **移动加权平均**；口径是**显式参数**，**报告页眉必须标注本次所用口径**，禁止"不写口径直接给成本"；
  - 口径切换**不修改原始流水**——成本是"原始流水 + 口径参数"的派生视图；
  - **费用三件套分摊**：佣金/印花税/过户费按交割单实际列值入账；交割单未分列的场合按**显式规则**（写在参数包里）分摊并在报告标注"分摊口径"，**不臆造费率**；
  - **T+1 与资金流水勾稽**：卖出当日资金可用/可取状态与资金本次余额的变化做勾稽，勾稽不平的行落 `invalid` 并列台账；
  - **每日持仓快照**：快照由成交流水确定性推导（同输入 → 同快照字节），不读时钟、不读外部行情。
- **验收**：与券商客户端展示的持仓比对，**持仓误差 ≤ 1 股、金额误差 ≤ 0.01 元**（阈值口径见 `data/README.md §四`）；两种口径各跑一遍，差异可解释到具体成交笔。

### 模块③ 公司行为还原

- **输入**：模块②的持仓台账 + 交割单中的公司行为行（分红、送转、配股、拆分、基金分红再投等）。
- **输出**：公司行为事件台账（事件类型 / 除权日 / 影响标的 / 份额调整 / 成本调整 / 税 / 依据行）+ **人工确认队列** + 还原后的成本与份额台账。
- **确定性纪律**：
  - **规则表 + 人工确认队列**双轨：规则表能确定识别的自动入账并**逐条挂依据**（命中哪条规则、哪个原始行）；规则无法确定的进**"待确认"队列**，用户确认后入账并留存确认记录（谁、何时、依据什么）；
  - **除权后的成本与份额调整**必须给出调整前后两组数（份额、单位成本、总成本），**调整可逆可追溯**；
  - **未识别行绝不静默丢弃**：无法归类即落 `待确认` 并出现在报告首页的"待处理"计数里，**不允许"跳过"成为默认行为**；
  - 送转/拆分引起的成本重算**不回写原始成交**，只作用于派生台账。
- **验收**：合成真值中植入的每一类公司行为（分红 / 送转 / 配股 / 拆分 / 分红再投）**逐笔对齐真值**；被刻意构造的"无法识别"行 100% 进待确认队列且报告可见。

### 模块④ 收益归因

- **输入**：模块②③的台账 + 期末市值（手工录入或本地 CSV）+ 可选的本地基准 CSV。
- **输出**：**XIRR（资金加权收益率）**、**TWR（时间加权净值曲线）**、已实现/未实现收益拆分、**费用拖累**、按**标的 / 行业 / 账户 / 年度**的收益分解、归因明细表。
- **确定性纪律**：
  - **XIRR 算法与收敛条件写死在参数包**（初始区间、迭代法、收敛阈值、最大迭代次数、无解时的明确报错），同一输入两次运行结果**逐位一致**；
  - **TWR 的估值点定义显式声明**（现金流日估值 vs 日历日估值），两种都不做"隐形插值"；
  - **已实现/未实现拆分**必须能对上总收益（拆分之和 = 总收益，差异 > 容忍度即报错）；
  - **费用拖累**只统计交割单中真实发生的费用，**不用估算费率**；
  - **基准数据只从本地 CSV 读**（用户自备），**不联网拉行情**；无基准时归因照常输出，只是不显示超额列；
  - **行业分类**来自用户可编辑的本地映射表，未分类标的统一落"未分类"**并在报告可见**。
- **验收**：XIRR 与 Excel 手工构造的 `XIRR` 结果对照，**误差 < 0.01%**（口径见 `data/README.md §四`）；同一输入重复运行输出字节一致；删除基准 CSV 后命令仍成功退出（退出码语义见 §三）。

### 模块⑤ 多账户合并与本地 HTML 报告

- **输入**：模块①–④的全部派生结果 + 用户登记的账户清单。
- **输出**：跨券商合并视图 + **单文件本地 HTML 报告** + 机读 `report_data.json`（与 HTML 同源）。
- **确定性纪律**：
  - **跨券商合并**：账户按用户登记归组，合并后每个标的同时保留"分账户明细"与"合计"；
  - **账户间资金划转抵消**：同一笔"从 A 转 B"的钱**不得在合并视图里被计成收益或成本**——识别为内部划转并同时从两端现金流剔除，划转台账逐笔可查；
  - **口径说明与可审计附录**：报告必须写清本次口径（成本法、XIRR 参数、TWR 估值点）、数据覆盖区间、异常行数、待确认数；
  - **每个数字可下钻**：报告中的成本、收益、费用单元格携带**原始行定位**（文件 SHA-256 + 行号 + 合同号/成交号），点击即在附录中高亮该行；
  - **敏感字段默认打码**：股东账号、资金账号默认只显示首尾片段，**打码发生在生成阶段**（不是靠 CSS 隐藏），报告从不携带完整账号；
  - **单文件 HTML**：零外链、零 CDN、零网络请求、零遥测；**断网全流程通过**。
- **验收**：断网环境（禁用网络）从导入到报告全流程退出码 0；HTML 静态扫描 **0 个外部资源引用**；同一输入重复生成报告**字节一致**；划转抵消用例在合并前后总收益不变。

### 扩展项（首期不做，不承诺交付）

- **基金 CSV / 手工录入模板**：场外基金份额与净值口径差异较大，先给手工模板与 CSV 通道，再谈自动识别；
- **PDF 交割单**：各家券商 PDF 排版无穷，**只声明覆盖度、不承诺 100%**，缺模板落 `unknown` 并列清单；
- **更多券商适配**：新增适配器必须附一份可复现的脱敏/合成样例，否则不进主干。

## 六、边界与非目标

- **不做投资建议（最重红线）**：**不荐股、不预测收益、不给交易信号、不做择时评价、不打分排名**。本工具只做"已经发生的钱怎么记、收益怎么拆"，**所有输出均为历史核算结果，不构成任何投资建议**。
- **不登录券商、不下单**：不保存任何券商账号密码、不调用任何券商接口、不做自动同步；**输入只能是用户自己在客户端点"导出"得到的文件**。这条同时是合规底线与隐私底线。
- **不做消费分类 / 不做预算 / 不做月度收支 / 不导入银行·支付宝·微信消费流水（硬切割）**：本题只处理**证券/基金账户的成交、持仓、公司行为与收益**。任何"这笔钱花在哪、这个月超支没有"的问题都不在本工具范围内。
- **不强制联网行情**：实时行情是**可选项**；核心链路（导入 → 成本 → 公司行为 → 归因 → 报告）**在断网环境下必须全流程可用**。不内置行情源、不爬取行情、不缓存行情。
- **不承诺"全券商支持"**：首期以 **2—3 家真实样例格式**（海通、华西为已实测基准）+ **通用列名映射** + **用户自定义模板**覆盖；未适配的券商落 `unknown` 并列清单，**不写"支持全部券商"**。
- **不做基金 PDF / 截图 OCR**：基金对账单 PDF 与客户端截图格式差异极大，列扩展项，**不进首期 DoD**。
- **隐私红线**：交割单含真实姓名、股东账号、资金账号、全部成交与余额，属**极敏感数据**。**纯本地零上传、零遥测、零账号体系**；报告生成阶段即对账号打码（不靠前端隐藏）；**真实交割单永不入仓**，仓库内样例一律程序化合成并用假代码/假账号白名单（见 `data/README.md §三`）。
- **免责红线**：本工具是**个人持仓核算辅助工具**，不是财务/税务/法律工具，也不是官方对账凭证；输出为基于导出文件的确定性核算结果，**与券商官方数据存在差异时以券商为准**。
- **品牌隔离**：与同方向其他项目代码零复制、文档互不提及对方业务；本题**只做投资账户**，不涉及任何消费流水领域。
- **首期范围限定**：模块①–⑤ 进首期 DoD；**基金 CSV/手工模板、PDF 交割单、更多券商适配一律为扩展项**，不在首期承诺交付。
