# plan/03 — 模块详设

> 五个模块的输入 / 输出 / 确定性纪律 / 验收，逐条对应 `plan/01 §二`。
> 数值口径引用 `data/README.md §四`，不复制。

## 通用约定

- **统一流水**是模块 ① 的输出、②③④ 的输入，字段见 `plan/02 §四`。
- **行级台账**（错误 / 待确认 / 划转 / 文件指纹）都是"每条可回放"的结构：
  必带 `source_file`、`source_sha256`、`source_line_no`，可选 `contract_no` / `trade_no`。
- **口径参数**（成本法、TWR 估值点、XIRR 参数、费用分摊规则）全部来自
  `data/rules/params.json`（M1 生成）与 CLI 显式参数，代码里不写第二份。
- 所有子命令支持 `--out-dir`，中间产物逐个落盘，可单步复查。

## M1 · 多券商导入适配层（已落地，2026-10-17）

> 实现位置：`src/investment_attribution/ingest/`（编码 / 壳清洗 / 表格读取 /
> 列名归一 / 值解析 / 记录构造 / 账户映射 / 文件编排）+ `pipeline/import_cmd.py`。
> 验收证据见 `plan/05 §M1`。

### 输入

用户在券商客户端自行导出的交割单文件，首期覆盖 `.xls` / `.xlsx` / `.csv` / `.tsv`。
已实测两类真实格式：

- **海通**：`.xlsx`，19 列（含股东账号 / 资金账号 / 三件套费用）
- **华西**：`.xls` 实为 **Tab 分隔文本** + `="..."` 单元格前缀 + **GB18030**

### 输出

1. 统一流水（字段见 `plan/02 §四`）
2. **行级错误台账**：原始行文本、行号、失败原因、失败代码
3. **文件指纹台账**：`sha256`、原文件名、导入时间（数据目录内的相对时间或显式参数，不读时钟）、行数
4. **账户—股东账号映射表**：用户显式登记，未登记落"待确认"

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| 编码探测白名单 | 显式顺序 `UTF-8(BOM) → UTF-8 → GB18030`；全失败即报错并列出文件；**不猜测、不静默替换字符** |
| `="..."` 清洗 | 仅剥离整个单元格包裹；剥离后仍非法 → `invalid`，**不做宽松修补** |
| 列名归一化 | 冻结别名表；未登记列记 `unknown`（行仍可用）；**列对齐不可信的行不入库** |
| 逐行错误台账 | 保留原始行文本 + 行号 + 失败原因，可原样回放 |
| SHA-256 去重 | 同内容文件识别为同一件；重复导入 0 重复流水；报告列出被跳过文件与首次导入时间 |
| 账户映射 | 不自动猜测；未登记落"待确认"，不并入默认账户 |

**格式判别按文件形态，不按扩展名**：`.xls` 可能是 Tab 文本，`.csv` 可能是
GB18030。判别顺序 = 编码探测 → 首行结构（分隔符与列名）→ 适配器选择；
未知形态**显式报错**，不静默归到默认解析器。

### 验收

- 同一文件重复导入 **0 重复流水**；改名 / 改扩展名同样识别为同一件
- 海通 / 华西两类样例 **100% 入库**，逐行列值与原文件一致、可回放
- 异常行清单逐条可回放：原始行文本 + 行号 + 原因
- 覆盖度：`manifest.coverage.surfaces` 中 9 个 `import.*` 形态，分子 = 分母

## M2 · 交易账本与成本引擎（已落地，2026-10-17）

> 实现位置：`src/investment_attribution/ledger/`（`model` 行语义 / `positions`
> 批次账与加权账 / `engine` 编排 / `verify` B2 比对）+ `pipeline/cost_cmd.py`。
> 口径细则唯一定义处 = `data/README.md §4.1`、§4.1.1；验收证据见 `plan/05 §M2`。

### 输入

模块 ① 的统一流水 + 显式成本口径 `--method fifo|wavg`。

### 输出

1. 逐笔持仓成本台账（批次明细 + 结转明细）
2. 每日持仓快照
3. 已实现 / 未实现收益
4. 费用明细（佣金 / 印花税 / 过户费 / 其他费分摊到笔）

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| 双口径 | FIFO 与移动加权都实现；口径是**显式参数，无默认值**；报告页眉强制标注 |
| 派生视图 | 口径切换**不修改原始流水**；成本 = 原始流水 + 口径参数的派生视图 |
| 费用三件套 | 按交割单实际列值入账；未分列时按参数包**显式分摊规则**并标注"分摊口径"；**不臆造费率** |
| T+1 勾稽 | 卖出当日资金可用/可取与资金本次余额变化勾稽；勾稽不平落 `invalid` 并列台账 |
| 每日快照 | 由成交流水确定性推导；同输入 → 同快照字节；不读时钟、不读外部行情 |

### 验收

- 与合成真值 B2 **逐笔对齐**；与券商客户端比对：持仓误差 **≤ 1 股**、金额误差 **≤ 0.01 元**
- 两种口径各跑一遍，差异**可解释到具体成交笔**
- 快照双跑字节一致
- 覆盖度：`cost.*` 5 个形态，含"双口径产生差异"的构造用例

## M3 · 公司行为还原

### 输入

模块 ② 的持仓台账 + 交割单中的公司行为行（分红 / 送转 / 配股 / 拆分 / 分红再投）。

### 输出

1. **公司行为事件台账**：事件类型 / 除权日 / 影响标的 / 份额调整 / 成本调整 / 税 / 依据行
2. **人工确认队列**：无法确定识别的行，含原始行与候选解释
3. **确认记录**：谁、何时、依据什么
4. 还原后的成本与份额台账（调整前后两组数）

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| 双轨 | 规则表能确定的自动入账并逐条挂依据（命中哪条规则、哪个原始行）；不能确定的进待确认队列 |
| 调整可逆 | 每次调整记录 before/after 的份额、单位成本、总成本；可回溯、可逆 |
| 未识别不丢 | 无法归类即落待确认，并出现在报告首页"待处理"计数里；**不允许"跳过"成为默认** |
| 不回写原始 | 送转 / 拆分引起的成本重算只作用于派生台账，不改写原始成交 |

**规则表形态**（M1 生成、冻结；M3 补齐判定字段）：
`{rule_id, business_name_patterns, event_type, expected_kinds, cash_effect,
share_factor | cash_per_share, tax_rule, requires_manual_confirm, evidence_hint}`，
外加顶层 `unmatched_policy` 与 `non_action_patterns`（银证转入/转出、内部划转等
资金划转的业务名模式）。

> M3 落地时发现：只有"业务名 → 事件类型"不足以判定一行该不该自动入账。
> "该事件应落在哪种行形态（`expected_kinds`）、现金往哪个方向（`cash_effect`）"
> 必须也由规则包声明，否则判定逻辑会退回代码里的 if，规则表就变成装饰。
> 详见 `data/README.md §4.1.2`（唯一口径处）。

### 验收（M3 已落地，2026-10-17）

- 合成真值 B3 中植入的每一类事件（分红 / 送转 / 配股 / 拆分 / 分红再投）**逐笔对齐**：
  `tests/test_actions.py::test_b3_matches_truth`（fifo / wavg 双口径）
- 刻意构造的"无法识别"行 **100% 进待确认队列**且产物可见（`actions.json.pending` +
  `pending.json`）：`test_unrecognized_row_lands_in_pending_queue`
- 调整前后两组数可逆复算：`test_every_adjustment_is_reversible`
- `other` 行三分桶守恒（事件 + 待确认 + 非行为 = 总数）：`test_other_rows_are_fully_bucketed`
- 覆盖度：`corporate_action.*` 6 个形态（含 `unrecognized_pending`），
  逐事件期望写在 `data/truth/actions_truth.json`

## M4 · 收益归因

### 输入

模块 ②③ 的台账 + 期末市值（手工录入或本地 CSV）+ 可选本地基准 CSV。

### 输出

1. **XIRR**（按账户 / 合并视图）
2. **TWR** 净值曲线（估值点口径显式声明）
3. 已实现 / 未实现拆分
4. **费用拖累**
5. 按**标的 / 行业 / 账户 / 年度**的收益分解
6. 归因明细表（每行可下钻）

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| XIRR 写死 | 初值、迭代法、收敛阈值、最大迭代次数、无解报错全部在 `params.json`；同一输入两次运行**逐位一致** |
| TWR 估值点 | `--twr-basis cashflow|daily` 显式声明；两种都不做**隐形插值**；缺市值日报 `VALUATION_MISSING` |
| 拆分守恒 | 已实现 + 未实现 = 总收益（差异 > 容忍度即报错） |
| 费用拖累 | 只统计交割单中**真实发生的费用**，不用估算费率 |
| 基准可选 | 只从本地 CSV 读；无基准时照常输出，只是不显示超额列 |
| 行业分类 | 用户可编辑的本地映射表；未分类统一落"未分类"**并在报告可见** |

### 验收（M4 已落地，2026-10-17）

- XIRR 与 Excel 手工构造的 `XIRR` 对照：**相对误差 < 0.01%**
  （`tests/test_attribution.py::test_b4_matches_truth_per_method`；
  另有闭式解算例 `test_xirr_matches_closed_form_manual_examples` 钉住绝对精度）
- 同一输入重复运行输出**字节一致**：`test_double_run_is_byte_identical`
- 删除基准 CSV 后命令仍成功退出（`exit 0`）且无超额列：
  `test_benchmark_absent_is_success_without_excess_columns`
- 零网络库 import 门禁 + 运行期 socket 探针 0 出网：
  `test_netguard.py`（静态 AST 阳性/阴性对照）+ `test_runtime_probe_blocks_real_socket_and_records`
  （运行期正/负对照）；拦截次数写进产物 `zero_upload.runtime_probe`
- 覆盖度：`attribution.*` 6 个形态（含负收益 / 零收益 / 期末市值为 0），
  逐形态期望与锚点写在 `data/truth/attribution_truth.json`：
  `test_every_attribution_surface_points_at_real_rows_and_carries_expectations` +
  `test_attribution_surface_expectations_are_concrete`
- 每账户 / 合并视图 XIRR 与真值一致；TWR 两种估值点口径各判一次；
  缺估值日日 `VALUATION_MISSING`；拆分守恒与四维分解各自之和等于总收益；
  费用总额等于 M2 `totals.fees_total_fen`

**实现位置**：`src/investment_attribution/attribution/`（`valuation` 估值表输入 /
`xirr` 求解器 / `twr` 净值连乘 / `benchmark` 可选基准 / `industries` 行业映射 /
`engine` 现金流·拆分·费用·四维分解 / `verify` B4 比对）+
`pipeline/attribution_cmd.py` 编排 + `netguard` 运行期探针。

> M4 落地时定下的关键口径：**外部现金流只取账户边界上的资金划转**
> （银证转入转出、内部划转），成交与分红不进外部流——它们是组合内部的
> "现金 ↔ 证券" 转换与收益实现。若把买入与银证转入同时计入，同一笔资本被计两次，
> XIRR 会凭空变成负几十个百分点。由此 `期末总资产 - 净投入 == 已实现 + 未实现`
> 对四个账户精确到分成立。完整口径见 `data/README.md §4.2.1` / §4.3.1（唯一口径处）。

## M5 · 多账户合并与本地 HTML 报告（已落地，2026-10-17）

### 输入

**归因产物 `attribution.json`**（已含分账户与合并两套数）+ 统一流水 `ledger.json`
（划转两腿要从原始行取证）+ 冻结规则包的 `transfer_patterns`。
**不重算成本**：合并只加"逐笔划转台账 + 守恒断言"这一层增量。

### 输出

1. 跨券商合并视图（分账户明细 + 合计）+ **逐笔划转台账**（合同号 / 两腿 / 已抵消证据）→ `merged.json`
2. **单文件本地 HTML 报告** → `report.html`
3. 机读 `report_data.json`（与 HTML 同源：同一次数据模型构建产出）

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| 跨券商合并 | 按账户归组；每个标的同时保留分账户明细与合计；合并持仓按标的汇总并记账户计数 |
| 划转抵消 | 模式取自规则包 `transfer_patterns`；按**合同号**归组，腿数 ≥ 2、净额恰为 0、两腿分属不同账户三条同时成立才算"已抵消"；否则落 `TRANSFER_LEG_UNPAIRED` / `TRANSFER_NET_NOT_ZERO` / `TRANSFER_SAME_ACCOUNT` 并 exit 1 |
| 合并前后守恒 | `Σ 各账户总收益 == 合并视图总收益`，差 > 0.01 元落 `MERGE_TOTAL_NOT_CONSERVED` |
| 口径说明 | 报告页眉复述成本法、TWR 估值点、外部现金流口径、估值日、基准是否提供；口径唯一来源仍是 `data/README.md §四` |
| 逐数字下钻 | 每个汇总数与每行表格携带 `source_file` / `source_sha256` / `source_line_no`；锚点取自上游 provenance 索引，**不造锚点** |
| 打码在生成阶段 | 股东账号 / 资金账号在**构建报告数据时**即打码（保留首尾各 2 位），构建末尾再跑一趟兜底替换；HTML / JSON 从不携带完整账号（不靠 CSS 隐藏） |
| 单文件 | 零外链、零 CDN、零网络请求、零遥测；出口扫描命中外部引用即报错且不落任何产物 |

**渲染层零判定**：`report/render.py` 只消费 `report/model.py` 的结论，
`report/guard.py` 的 AST 门禁锁死三条（每条配阳性与阴性对照）：

1. `R1_cost_method`：不得按成本口径分支（`fifo` / `wavg` / `cost_method`）
2. `R2_event_type`：不得按事件或行形态分支（`event_type` / `dividend` / `split` / `trade_buy` …）
3. `R3_return_basis`：不得重新解释收益构成（`realized` / `unrealized` / `total_return` / `xirr` / `twr` …）

判定词表覆盖**字符串字面量、标识符、属性名**三类载体；与业务词同形的标准库方法名
（`split` / `join` / `get` …）列进白名单，只作方法名放行。

**零外链口径**：单文件内嵌样式、无内联脚本、无 `<link>/<img>/<iframe>/@import`；
出口扫描对 `http://` / `https://` / `//` 三种标记一律判红——协议相对地址一样会在
打开报告时发起外部请求，"看起来不像链接"不是放行的理由。

> **与原始计划的偏差（有意为之）**：原计划的零判定三条是"不 import 引擎 /
> 不做算术运算 / 不内联阈值字面量"。落地改为**按业务判定面切三条**，理由有二：
> ① 原三条只挡实现手法（import / 算术），挡不住"在模板里写 `if method == "fifo"`"
> 这类真正的判定；② "不做算术"会把 `fen → 元` 的纯展示换算也判红，那是
> 展示而非判定。改成按业务词判之后，阳性对照能直接写成"贴一句判定必须红"。
> 另：`run --out-dir` 由"缺省 `out/`"改为**必填**（CWD 兜底会让在哪个目录敲命令
> 改变结果，与 K4 同一条理由）；`run` 的口径参数由 `--cost-method` 统一为 `--method`。

### 验收（M5 已落地，2026-10-17）

- 零网络下从导入到报告全流程跑通：`attribution` / `merged` / `report_data` 三处
  运行期探针 `blocked_attempts == 0`；`merge` / `report` 两条命令在随包样例上 `exit 0`
  （`run` 返回 1 是数据结论：样例含一条规则表认不出的现金行 → `corporate-actions` 按契约返回 1）
- HTML 静态扫描 **0 个外部资源引用**（三形态阳性对照 + 注入外链必须报错且不落产物）
- 同一输入重复生成报告**字节一致**（HTML 与 JSON 各自逐字节比对）
- 划转抵消用例在合并前后总收益不变（`difference_fen == 0`，门槛 ≤ 0.01 元）
- 报告静态扫描无完整账号形态；打码发生在生成阶段（构建模型即打码 + 兜底替换）
- 每个汇总数（8 个）与每行表格（41 行）都可定位到原始行，锚点回查 upstream 时 sha256 与样例字节一致
- `run` 与逐命令 13 份产物**逐字节一致**
- 覆盖度：`merge.*` 4 个形态（两账户 / 三账户 / 账户间划转 / 同名标的重叠持仓）逐项期望写进
  `data/truth/merge_truth.json`

## 跨模块：编排与调用链

```
run
 ├─ import   → ledger.json / import_errors.json / fingerprints.json / account_map.json
 ├─ cost     → holdings.json / snapshots.json（按 --method）
 ├─ pnl      → pnl.json（固定带 --fees）
 ├─ corporate-actions → actions.json / pending.json
 ├─ attribution → attribution.json（XIRR / TWR / 分解）
 ├─ merge    → merged.json（合并视图 + 逐笔划转台账）
 └─ report   → report.html / report_data.json
```

- 每个中间产物落 `--out-dir`，单步可复查。
- `run` 与逐个手敲子命令的产物**逐字节一致**（同一目录、同一路径字符串下断言 13 份产物）。
- `run` 不读时钟、不联网；`--out-dir` **必填**（不设缺省，理由同 K4）。

| B1 | 导入适配 | `ingest/verify.py` | 逐行列值 / 行级错误 / 文件指纹对齐导入真值；两类真实格式 100% 入库；异常行逐条可回放 |
| B2 | 成本引擎 | `ledger/verify.py` | 双口径逐笔对齐真值；费用分摊逐笔；快照双跑一致 |
| B3 | 公司行为 | `actions/verify.py` | 逐类事件对齐；无法识别 100% 进待确认 |
| B4 | 归因 | `attribution/verify.py` | XIRR 对 Excel 手工；TWR 估值点；拆分守恒；费用拖累可复算 |
| B5 | 合并与报告 | `merge/verify.py` | 合并前后总收益不变；逐笔划转台账；合并持仓与账户计数 |

`bench` 只做**总入口与失败码汇总**，五套判据分别来自上表五个模块的 `verify.py`，
它自己不长第二套计算路径；`--only B1..B5` 可选单个套件，未识别套件名即 `exit 2`。

**真值纪律**：真值库只存"输入 + 期望"，观测由基准运行时实算；
真值库出现 `observed_*` 类字段即判红。每套件配**可证伪探活**：
注入一个缺陷 → 该套件必须报未达标。
