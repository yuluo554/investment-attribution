# plan/03 — 模块详设

> 五个模块的输入 / 输出 / 确定性纪律 / 验收，逐条对应 `plan/01 §二`。
> 数值口径引用 `data/README.md §四`，不复制。

## 通用约定

- **统一流水**是模块 ① 的输出、②③④ 的输入，字段见 `plan/02 §四`。
- **行级台账**（错误 / 待确认 / 划转 / 文件指纹）都是"每条可回放"的结构：
  必带 `source_file`、`source_sha256`、`source_line_no`，可选 `contract_no` / `trade_no`。
- **口径参数**（成本法、TWR 估值点、XIRR 参数、费用分摊规则）全部来自
  `data/rules/params.json`（M1 生成）与 CLI 显式参数，代码里不写第二份。
- 所有子命令支持 `--out-dir`，中间产物逐个落盘，可单步复查。

## M1 · 多券商导入适配层（已落地，2026-10-17）

> 实现位置：`src/investment_attribution/ingest/`（编码 / 壳清洗 / 表格读取 /
> 列名归一 / 值解析 / 记录构造 / 账户映射 / 文件编排）+ `pipeline/import_cmd.py`。
> 验收证据见 `plan/05 §M1`。

### 输入

用户在券商客户端自行导出的交割单文件，首期覆盖 `.xls` / `.xlsx` / `.csv` / `.tsv`。
已实测两类真实格式：

- **海通**：`.xlsx`，19 列（含股东账号 / 资金账号 / 三件套费用）
- **华西**：`.xls` 实为 **Tab 分隔文本** + `="..."` 单元格前缀 + **GB18030**

### 输出

1. 统一流水（字段见 `plan/02 §四`）
2. **行级错误台账**：原始行文本、行号、失败原因、失败代码
3. **文件指纹台账**：`sha256`、原文件名、导入时间（数据目录内的相对时间或显式参数，不读时钟）、行数
4. **账户—股东账号映射表**：用户显式登记，未登记落"待确认"

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| 编码探测白名单 | 显式顺序 `UTF-8(BOM) → UTF-8 → GB18030`；全失败即报错并列出文件；**不猜测、不静默替换字符** |
| `="..."` 清洗 | 仅剥离整个单元格包裹；剥离后仍非法 → `invalid`，**不做宽松修补** |
| 列名归一化 | 冻结别名表；未登记列记 `unknown`（行仍可用）；**列对齐不可信的行不入库** |
| 逐行错误台账 | 保留原始行文本 + 行号 + 失败原因，可原样回放 |
| SHA-256 去重 | 同内容文件识别为同一件；重复导入 0 重复流水；报告列出被跳过文件与首次导入时间 |
| 账户映射 | 不自动猜测；未登记落"待确认"，不并入默认账户 |

**格式判别按文件形态，不按扩展名**：`.xls` 可能是 Tab 文本，`.csv` 可能是
GB18030。判别顺序 = 编码探测 → 首行结构（分隔符与列名）→ 适配器选择；
未知形态**显式报错**，不静默归到默认解析器。

### 验收

- 同一文件重复导入 **0 重复流水**；改名 / 改扩展名同样识别为同一件
- 海通 / 华西两类样例 **100% 入库**，逐行列值与原文件一致、可回放
- 异常行清单逐条可回放：原始行文本 + 行号 + 原因
- 覆盖度：`manifest.coverage.surfaces` 中 9 个 `import.*` 形态，分子 = 分母

## M2 · 交易账本与成本引擎（已落地，2026-10-17）

> 实现位置：`src/investment_attribution/ledger/`（`model` 行语义 / `positions`
> 批次账与加权账 / `engine` 编排 / `verify` B2 比对）+ `pipeline/cost_cmd.py`。
> 口径细则唯一定义处 = `data/README.md §4.1`、§4.1.1；验收证据见 `plan/05 §M2`。

### 输入

模块 ① 的统一流水 + 显式成本口径 `--method fifo|wavg`。

### 输出

1. 逐笔持仓成本台账（批次明细 + 结转明细）
2. 每日持仓快照
3. 已实现 / 未实现收益
4. 费用明细（佣金 / 印花税 / 过户费 / 其他费分摊到笔）

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| 双口径 | FIFO 与移动加权都实现；口径是**显式参数，无默认值**；报告页眉强制标注 |
| 派生视图 | 口径切换**不修改原始流水**；成本 = 原始流水 + 口径参数的派生视图 |
| 费用三件套 | 按交割单实际列值入账；未分列时按参数包**显式分摊规则**并标注"分摊口径"；**不臆造费率** |
| T+1 勾稽 | 卖出当日资金可用/可取与资金本次余额变化勾稽；勾稽不平落 `invalid` 并列台账 |
| 每日快照 | 由成交流水确定性推导；同输入 → 同快照字节；不读时钟、不读外部行情 |

### 验收

- 与合成真值 B2 **逐笔对齐**；与券商客户端比对：持仓误差 **≤ 1 股**、金额误差 **≤ 0.01 元**
- 两种口径各跑一遍，差异**可解释到具体成交笔**
- 快照双跑字节一致
- 覆盖度：`cost.*` 5 个形态，含"双口径产生差异"的构造用例

## M3 · 公司行为还原

### 输入

模块 ② 的持仓台账 + 交割单中的公司行为行（分红 / 送转 / 配股 / 拆分 / 分红再投）。

### 输出

1. **公司行为事件台账**：事件类型 / 除权日 / 影响标的 / 份额调整 / 成本调整 / 税 / 依据行
2. **人工确认队列**：无法确定识别的行，含原始行与候选解释
3. **确认记录**：谁、何时、依据什么
4. 还原后的成本与份额台账（调整前后两组数）

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| 双轨 | 规则表能确定的自动入账并逐条挂依据（命中哪条规则、哪个原始行）；不能确定的进待确认队列 |
| 调整可逆 | 每次调整记录 before/after 的份额、单位成本、总成本；可回溯、可逆 |
| 未识别不丢 | 无法归类即落待确认，并出现在报告首页"待处理"计数里；**不允许"跳过"成为默认** |
| 不回写原始 | 送转 / 拆分引起的成本重算只作用于派生台账，不改写原始成交 |

**规则表形态**（M1 生成、冻结）：`{rule_id, business_name_patterns, event_type,
share_factor | cash_per_share, tax_rule, requires_manual_confirm, evidence_hint}`。

### 验收

- 合成真值 B3 中植入的每一类事件（分红 / 送转 / 配股 / 拆分 / 分红再投）**逐笔对齐**
- 刻意构造的"无法识别"行 **100% 进待确认队列**且报告可见
- 调整前后两组数可逆复算
- 覆盖度：`corporate_action.*` 6 个形态（含 `unrecognized_pending`）

## M4 · 收益归因

### 输入

模块 ②③ 的台账 + 期末市值（手工录入或本地 CSV）+ 可选本地基准 CSV。

### 输出

1. **XIRR**（按账户 / 合并视图）
2. **TWR** 净值曲线（估值点口径显式声明）
3. 已实现 / 未实现拆分
4. **费用拖累**
5. 按**标的 / 行业 / 账户 / 年度**的收益分解
6. 归因明细表（每行可下钻）

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| XIRR 写死 | 初值、迭代法、收敛阈值、最大迭代次数、无解报错全部在 `params.json`；同一输入两次运行**逐位一致** |
| TWR 估值点 | `--twr-basis cashflow|daily` 显式声明；两种都不做**隐形插值**；缺市值日报 `VALUATION_MISSING` |
| 拆分守恒 | 已实现 + 未实现 = 总收益（差异 > 容忍度即报错） |
| 费用拖累 | 只统计交割单中**真实发生的费用**，不用估算费率 |
| 基准可选 | 只从本地 CSV 读；无基准时照常输出，只是不显示超额列 |
| 行业分类 | 用户可编辑的本地映射表；未分类统一落"未分类"**并在报告可见** |

### 验收

- XIRR 与 Excel 手工构造的 `XIRR` 对照：**相对误差 < 0.01%**
- 同一输入重复运行输出**字节一致**
- 删除基准 CSV 后命令仍成功退出（`exit 0`）
- 零网络库 import 门禁 + 运行期 socket 探针 0 出网
- 覆盖度：`attribution.*` 6 个形态（含负收益 / 零收益 / 期末市值为 0）

## M5 · 多账户合并与本地 HTML 报告

### 输入

模块 ①–④ 的全部派生结果 + 用户登记的账户清单 + 划转台账。

### 输出

1. 跨券商合并视图（分账户明细 + 合计）
2. **单文件本地 HTML 报告**
3. 机读 `report_data.json`（与 HTML 同源：同一次渲染产生）

### 确定性纪律

| 纪律 | 落地 |
|---|---|
| 跨券商合并 | 按用户登记归组；每个标的同时保留分账户明细与合计 |
| 划转抵消 | 识别账户间内部划转，**同时从两端现金流剔除**；划转台账逐笔可查 |
| 口径说明 | 报告写清成本法、XIRR 参数、TWR 估值点、数据覆盖区间、异常行数、待确认数 |
| 逐数字下钻 | 成本 / 收益 / 费用单元格携带 `file_sha256 + line_no + contract_no`；点击在附录高亮 |
| 打码在生成阶段 | 股东账号 / 资金账号只显示首尾片段；HTML 从不携带完整账号（不靠 CSS 隐藏） |
| 单文件 | 零外链、零 CDN、零网络请求、零遥测；断网全流程通过 |

**渲染层零判定**：`report/` 只消费引擎结论，AST 门禁锁死以下三条
（每条配阳性与阴性对照）：

1. 不 import 引擎模块
2. 不做算术运算（`BinOp`，豁免模板 `%` 与字符串拼接）
3. 不内联口径数值 / 阈值字面量

**零外链口径**：渲染资源零外部引用（`<script>/<link>/<img>/<iframe>`、
`@import`、CSS `url(https://…)`）；条目自带的原文 URL 属内容字段，
`<a href>` **放行**。断言常驻渲染出口，不只在测试里验一次。

### 验收

- 断网环境从导入到报告全流程 `exit 0`
- HTML 静态扫描 **0 个外部资源引用**
- 同一输入重复生成报告**字节一致**
- 划转抵消用例在合并前后总收益不变（≤ 0.01 元）
- 报告静态扫描无完整账号形态
- 每个汇总数抽查均可定位到原始行
- 覆盖度：`merge.*` 4 个形态

## 跨模块：编排与调用链

```
run
 ├─ import   → ledger.json / errors.json / fingerprints.json
 ├─ cost     → holdings.json（按 --cost-method）
 ├─ pnl      → pnl.json
 ├─ corporate-actions → actions.json / pending.json
 ├─ attribution → attribution.json（XIRR / TWR / 分解）
 ├─ merge    → merged.json（含划转抵消）
 └─ report   → report.html / report_data.json
```

- 每个中间产物落 `--out-dir`，单步可复查。
- `run` 与逐个手敲子命令的产物**逐字节一致**（三方对账测试）。
- `run` 全程不读时钟、不联网；`--out-dir` 缺省为 `out/`（已 gitignore）。

## 基准套件 B1–B5

| 套件 | 对象 | 关键断言 |
|---|---|---|
| B1 | 导入适配 | 两类真实格式 100% 入库；重复导入 0 重复；异常行逐条可回放 |
| B2 | 成本引擎 | 双口径逐笔对齐真值；费用分摊逐笔；快照双跑一致 |
| B3 | 公司行为 | 逐类事件对齐；无法识别 100% 进待确认 |
| B4 | 归因 | XIRR 对 Excel 手工；TWR 估值点；拆分守恒；费用拖累可复算 |
| B5 | 合并与报告 | 合并前后总收益不变；0 外链；双跑字节一致；下钻可定位 |

**真值纪律**：真值库只存"输入 + 期望"，观测由基准运行时实算；
真值库出现 `observed_*` 类字段即判红。每套件配**可证伪探活**：
注入一个缺陷 → 该套件必须报未达标。
