# plan/00-README 总览

仓库 `10-17-investment-attribution`（券商交割单收益归因工作台）出题阶段总览。v1（2026-10-17，出题阶段 4 骨架完成）。
**M4 已落地（2026-10-17）**：可运行 CLI + 退出码契约 + 可证伪自检 + 零上传静态门禁**与运行期 socket 探针** + 确定性写盘；
M1-M4 业务模块（导入 / 成本 / 公司行为 / 归因）已填充，其余按 M5-M6 收尾。

**项目**：把券商客户端导出的交割单还原成一本可审计的投资账——持仓成本、已实现/未实现收益、分红送转还原、多账户合并、XIRR/TWR 归因，每个数字可下钻到原始行。
**方法论**：数据先行 + 冻结产物 + 合成真值基准 + 确定性规则引擎 + 纯本地交付。
**交付形态**：**纯本地 Python CLI + 本地 HTML 报告**（无服务器、无 GPU、不登录券商、不联网行情、零上传零遥测）。
**命名约定**：本地目录 `10-17-investment-attribution`（`10-17` = 2026-10-17 日期标签）；**GitHub 仓库名 = `investment-attribution`（纯净名，去日期前缀）**，沿用 `yuluo554/<kebab-name>` 惯例；署名 `yuluo554`。
**命名纪律**：全程使用 **投资账 / 归因 / 持仓台账** 词系，避开"账单 / 记账 / 收支"词系（与本方向已有的消费流水类项目硬切割）。
**定位宣言**：把券商客户端导出的交割单还原成一本可审计的投资账：持仓成本、已实现/未实现收益、分红送转还原、多账户合并、XIRR/TWR 归因，每个数字可下钻到原始行。**不做投资建议，只做账**。同花顺账本在云端要账号，beancount 要会计素养，本工具零上传、不登录、中文券商格式开箱即用。

| 2026-10-17 | 估值样例升级为**多日估值序列**（37 日 x 7 标的），价格按交易日锚定 + 送股/拆分在**复权空间**插值后还原 | 期末单点市值不足以让 TWR 分段；引擎侧**不做插值**（K8：口径不藏进代码）。复权空间插值保证送股/拆分前后市值连续，否则 0 成本份额会让 TWR 出现假跳变 |
| 2026-10-17 | 运行期零上传探针用 `sys.addaudithook`，**不 import socket** | 静态 AST 门禁禁止包源码 import 任何网络库；若探针自己 `import socket` 就会被自家门禁拦下（自相矛盾）。审计钩子只按事件名前缀判定，不依赖任何网络模块 |
| 2026-10-17 | 估值表数量与台账持仓**交叉核对**，超 1 股容差落 `VALUATION_QUANTITY_MISMATCH` | 估值表是用户手工给的，若它说 2000 股而台账是 7000 股，市值就是错的。这条不是"可用性增强"而是**防止静默算错**：让两个来源打架时显式报出来 |
