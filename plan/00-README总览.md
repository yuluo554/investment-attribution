# plan/00-README 总览

仓库 `10-17-investment-attribution`（券商交割单收益归因工作台）出题阶段总览。v1（2026-10-17，出题阶段 4 骨架完成）。
**M0 骨架已落地（2026-10-17）**：可运行 CLI + 退出码契约 + 可证伪自检 + 零上传静态门禁 + 确定性写盘；业务模块按 M1–M5 逐个填充。

**项目**：把券商客户端导出的交割单还原成一本可审计的投资账——持仓成本、已实现/未实现收益、分红送转还原、多账户合并、XIRR/TWR 归因，每个数字可下钻到原始行。
**方法论**：数据先行 + 冻结产物 + 合成真值基准 + 确定性规则引擎 + 纯本地交付。
**交付形态**：**纯本地 Python CLI + 本地 HTML 报告**（无服务器、无 GPU、不登录券商、不联网行情、零上传零遥测）。
**命名约定**：本地目录 `10-17-investment-attribution`（`10-17` = 2026-10-17 日期标签）；**GitHub 仓库名 = `investment-attribution`（纯净名，去日期前缀）**，沿用 `yuluo554/<kebab-name>` 惯例；署名 `yuluo554`。
**命名纪律**：全程使用 **投资账 / 归因 / 持仓台账** 词系，避开"账单 / 记账 / 收支"词系（与本方向已有的消费流水类项目硬切割）。
**定位宣言**：把券商客户端导出的交割单还原成一本可审计的投资账：持仓成本、已实现/未实现收益、分红送转还原、多账户合并、XIRR/TWR 归因，每个数字可下钻到原始行。**不做投资建议，只做账**。同花顺账本在云端要账号，beancount 要会计素养，本工具零上传、不登录、中文券商格式开箱即用。

- **数值口径一处定义**（`data/README.md §四`），引擎 / 报告 / 基准全部引用同一份，禁止手写第二份口径。
- **冻结产物禁手改**（列名别名表、公司行为规则表、参数包、真值台账）：改需求走生成器整目录重生成 + `--check` 位级守门。
- **诚实口径**：未推送 = 未跑 CI；DoD 中的"CI 绿"在无远端时必须写成"本地等价校验，待首推验证"。
  **当前状态（2026-10-17）**：本地等价校验 = 3.8 / 3.12 双解释器全量 pytest 通过；
先落盘（2026-10-17），M1 开工后**按末态回填**：M1 落地时点实为 3.8 / 3.12 双解释器全量 pytest 通过 + `gen_data.py --check` 双层全绿；
  **未接远端，CI 待首推验证**（CI 已补 `gen_data.py --check` 与导入冒烟两步，均未实跑）。
- **M0 的"本地等价校验"等价物清单**（可指认的替代证据）：3.8 与 3.12 各跑一遍全量 pytest；
  `selftest --strict` 在真实数据目录 exit 0、在空目录 exit 2；未落地命令 exit 3 手动冒烟；
  README 指令面门禁（`python -m` 可执行 + 路径存在 + extras 双向对账）。
  **缺口**：CI 的 windows/ubuntu 环境差异未验证，待 M6 首推。
- **每个里程碑出口的硬约束**：DoD 验证 → 本文件状态回写 → 写 `plan/HANDOFF-M<next>.md` → commit →（有远端则 push 等 CI 绿）。
- **隐私红线**：合成样例一律假证券代码 / 假账号白名单（见 `data/README.md §三`）；真实交割单永不入仓。
- **品牌隔离**：文档不提及同方向其他项目；切割线只写"聚焦投资账户，不做消费流水"。
- **发布纪律**：M6 三件套措辞不裁剪；发布留档在 tag 前落盘，tag 后才产生的事实（CI run id / 附件 sha256 / 真下载复核）作为追加提交并**分栏**记录。
